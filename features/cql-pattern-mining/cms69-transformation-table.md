## Sem-and / sem-or composition rule (v2)

Reviewed in round 1; clarified here as the authoritative rule the table applies:

- **All operands same shape, same `(T, V)`**: composition is that shape, that `(T, V)`. Refinement of `SR+CodeableConcept` and `SR+CodeableConcept` = `SR+CodeableConcept` (list intersection / union / difference). Boolean and boolean = boolean.
- **All operands boolean (Observation+boolean) but conceptually "over" different resources**: still `Observation+boolean`. Boolean composition.
- **Mixed shapes** (one refinement, one boolean): **defect.** No silent conversion. Either refactor to all-boolean (existence-wrap each refinement explicitly) or all-refinement (drop the boolean). Validator flags it.
- **Heterogeneous resources** (refinements of different FHIR types): **model limitation.** CRL has no `DomainResource` umbrella. The accepted workaround is `Observation+boolean` with a documented note. Issue tracked for future model extension.
