# CRL Release Notes content

CRL produces versioned release content. Spaces owns the combined editor experience, its startup, the **KALM AI: What's New** command (`kalm.showReleaseNotes`) and per-codespace/per-component history. CRL does not launch a notes tab, register a separate reopen command, read a KELP project, or mutate notes history. Standalone CRL does not automatically present notes. Existing producer history keys remain inert; CRL neither migrates nor deletes them.

The shared [provider contract](release-notes-provider-contract.md) is data-only. No producer imports another extension's code. Spaces is authoritative for the delivery/consumer contract; KELP independently produces its own conforming content.

## Authoring

Maintain `packages/crl-vscode/media/release-notes/catalog.json` and local PNG/WebM media. Keep unique ascending stable release versions after `baselineVersion`, with nonempty feature titles/descriptions. Titles are at most120Unicode code points, descriptions2000, and alt/captions300. Titles/alt/captions are single-line; only descriptions allow LF. Other C0 controls, DEL, U+2028 and U+2029 are invalid. At most100releases and20features per release. Images require `alt`; a video requires a PNG poster, alt and visible caption. Prefer short silent VP8 WebM only where motion is useful. Screenshots must show actual CRL behavior with synthetic content, with no customer data, credentials or personal information.

The maintained directory contains exactly catalog.json, generated README.md and referenced media. Run `npm run notes:write -w crl-language-support`, review README, then `npm run notes:check -w crl-language-support`. The latter reports source and delivered catalog byte sizes. Budget before adding content: provider.json4KiB, delivered catalog256KiB, each PNG2MiB and4096×4096pixels, all distinct media5MiB and all videos1MiB cumulatively. Lowercase flat filenames (including dots, never `..`), regular files, PNG IHDR dimensions and PNG/WebM signatures are validated. Retain codec evidence and actual playback for any VP8/VP9 WebM; no video ships today. Bounds apply before packaging; resolve a history-budget problem with Spaces rather than silently discarding supported history.

Source catalogs and README can contain future drafts. Ordinary checks/builds do not require a current-version release entry. Provider delivery filters to the actual manifest version's stable base and includes only referenced media. A development package with no eligible history omits the descriptor and clears stale generated content; that is not a public release. Strict public preflight requires the latest source entry to equal the release version.

## Build and packaging

The extension compile stages generated `packages/crl-vscode/release-notes/`, deriving provider version from that extension's package.json. The folder is ignored by Git. Staging validates all inputs before replacing only verified regular files in that fixed, flat output directory; links, directories and unexpected files fail rather than being followed or recursively deleted. No timestamps or nondeterministic metadata enter the provider JSON. A fresh build removes formerly referenced media.

The installed VSIX root contains `release-notes/provider.json`, catalog.json and referenced media. Actual ZIP entries start with `extension/release-notes/`. Maintained media/release-notes/ inputs, README and scripts are excluded from the delivered provider. The staged catalog is canonical filtered JSON, not necessarily byte-identical to the unfiltered source catalog; delivered media are exact validated source bytes.

`npm run package:release -w crl-language-support` runs strict content preflight, creates the versioned VSIX, then automatically verifies that actual archive with `scripts/verify-release-notes.mjs`. The verifier rejects missing/stale/extra/duplicate provider entries, old source payloads, version mismatches and retired CRL command/history wiring. It compares actual provider bytes with the canonical source projection. `yauzl` and AJV2020 are declared build-only. AJV checks the byte-identical pinned Spaces schemas; neither dependency is bundled into the extension or SDK. The archive gate also rejects unbundled node_modules. Inspect those same verified VSIX bytes during installed qualification and publish them without rebuilding a second copy.

## Portable downloads and provenance

`node packages/crl-vscode/scripts/release-notes.mjs --export <output> [--mode publish|dry-run]` keeps the existing versioned HTML and Markdown downloads. HTML embeds its media and works offline. Public Markdown links to the illustrated download rather than private raw media. Bundled source README retains all authored history with relative media. Public preflight is strict; rehearsal permits later source drafts but excludes them from its selected range.

For these portable downloads and the GitHub body, `deployedBaselineVersion` still selects the catch-up range. Obtain it from Spaces' actual deployment receipts each release; a software tag is not evidence of deployment. Reconcile differing target baselines and retained history without inventing a receipt. The same fields in the delivered provider are informational only: Spaces uses its own deployment baseline and history for the combined view. Historical entries describe their original released behavior; they do not preserve retired current launch rules. Existing published release assets remain immutable.

Generate the actual GitHub body with `node packages/crl-vscode/scripts/release-notes.mjs --body <source-SHA> tmp/RELEASE_NOTES_vX.Y.Z.md`. It requires clean committed source and exact current HEAD, then places the trusted publisher marker before authored content. Regenerate after HEAD changes. Keep HTML/MD in the explicit publisher asset list and SHA256SUMS. Provider data travels in the hash-pinned VSIX; there is no extra ZIP or runtime registration API.

## Qualification and handoff

Run relevant content/export/CLI/provider/provenance tests, typecheck/build, actual VSIX verification and installed checks. Exercise negative archive controls, including missing descriptor and changed media, and observe the verifier fail before restoring the canonical artifact. Verify retired reader commands/settings/history code are absent from the installed manifest/runtime; a fresh normal Code profile must not open a CRL notes tab or write its old marker. Do not seed, migrate or delete user history. Check portable HTML media decoding and fragment navigation offline. Other CRL native, kit and full release gates remain as required by the release skill.

Give Spaces extension ID `smiledigitalhealth.crl-language-support`, retained floor and factual portable-export receipt (Spaces chooses its own consumer baseline), immutable source/tag, the actual VSIX/engine URLs and checksums, contained server/driver identities, provider contract/version, portable download links and a user-facing summary. Record acknowledgment and the separate Spaces launcher/validate receipt when available; local schema checks do not claim that receipt. Spaces' deployment qualification must use the actual installed launcher in Codespaces to locate/read both provider descriptors, catalogs and media through extension URIs, then verify the combined UI/startup/opt-out/history/navigation. A CRL producer pass does not certify that consumer behavior, and software publication does not imply image deployment or customer-notice approval.

`package:release` is the strict public-artifact path. Ordinary development VSIX packaging uses `vsce package --no-dependencies` after the normal compile, without the public current-entry gate. Portable export rehearsal uses `--mode dry-run`; it does not redefine public packaging or relax its checks.

Previously authored user settings or keybindings referencing the removed CRL reader may remain unknown/unresolved in VS Code. CRL does not rewrite user configuration or retain deprecated producer contributions; Spaces owns the replacement command and automatic-opening preference. Old CRL notes history was extension globalState, not a contributed user setting, and remains inert.

Maintainer compilation validates the source catalog, media and generated README; finish the catalog edit and run `npm run notes:write -w crl-language-support` before compiling. This deliberate authoring-time gate does not run in the installed producer extension. To export with the npm shortcut, use `npm run notes:export -w crl-language-support -- <output-directory>` (append `--mode dry-run` for rehearsal). Record the actual base64-expanded portable HTML size. Before adding a video, verify the file contains no audio track as well as the supported codec and actual playback.

## Editorial audience

Write user feature descriptions for nurses and informaticists. Explain the visible task and benefit in plain language. Keep runtime/build/security-dependency identities and deployment mechanics in maintainer evidence. Do not announce the notes feature in the notes. Explicit operator curation can remove irrelevant historical entries; version gaps are allowed and do not change actual deployment receipts or the retained floor. Past published releases remain immutable.
