Nautilus maintains its run/assignment identity without a new shared pass-ID protocol.

## KELP intake and permissions

For the pilot, KELP Add took the original HTML as primary source; an authorized content editor then locked source, added the text extract and metadata as companion files, Saved source, and released the source lock. Do not hand-edit `.kelp` records. That intake is observed; the revised target workflow makes Add enter Ready to codify, but current KELP did not apply that status. If that card is earlier than the parent's current configured stage, KELP opens or reuses its rework subtask without advancing the parent; otherwise it writes the card's configured in-progress status to the parent. `Unlock from=card` releases the locks and completes the matching rework subtask once that card's locks are released. Explicit Complete performs the card's configured next-ready handoff. On the normal path it moves the parent; after earlier-card rework it creates or reuses linked next-stage work while preserving the advanced parent. The assisted route uses SaveCodify; direct canonical work uses KELP Save where changed entities need delivery. KELP preserves Nautilus-written preparation statuses on ordinary refresh. During earlier-stage assisted rework, Nautilus puts its preparation statuses on linked work rather than overwriting the advanced parent; the exact run-to-rework association remains to be implemented and qualified.
