# Supervised codification Codespace pilot

Status: **integration draft**, 2026-10-11. CRL is the cross-project design and decision point; KELP, Automation, Spaces, and the KE pipeline owner retain implementation responsibility for their components. This record separates agreed direction, released capabilities, proposals, and open acceptance work. It does not authorize publication, attest to human Medical Validation, or claim that a Codespace or artifact has been created.

## Decisions and scope

- **Human-supervised run.** An operator works with the Nautilus orchestrator skill and an agent to prepare a batch for a loaded artifact. A separate codifier may discover it later, Lock the scopes and run the interactive KE lead in their Codespace. Headless execution is outside this pilot's acceptance path. The authoring Codespace has one Git checkout: the content repository on the artifact branch. The codifier works in VS Code's Claude Code chat at that checkout root. There is no separate KE-agent worktree or persistent orchestrator agent.
- **Pilot target.** Under the operator's cross-project decision delegation, CRL selected the source-only `smile-digital-health/smile-demo-codification` repository and `artifact/auto-bleph`. Spaces reports that the repository does not yet exist; its operator must create it. The existing `smile-demo` repository and deployed bleph encoding stay untouched. This is an infrastructure and workflow pilot; no blind authoring efficacy claim follows merely from source-only isolation.
- **Source.** Intake uses only the committed L34194 source snapshot from `smile-demo` commit `7a2b7f2de63fc441dba99ceed2b4aa57eb32a2dc`: `L34194-v27-2025-10-16.html` SHA-256 `0cd904938597f99bf05d9dfc86209c8e3d34dada1107ddd802dc04b680db6357`; text extract `.txt` SHA-256 `de332387e3a1bb3fb6720f592677eedef7ea988cd112917d087debb82a387e6f`; `.metadata.json` SHA-256 `684b35d673824695a1e78772c00185d2ebbe90c59375a4c6925d1f9cda3660a7`. The metadata's embedded hashes differ from the committed bytes; freeze the committed files and record that discrepancy without silently altering either. Check the pilot tree before its first push: prior `smile-demo` refined-source, anchor-source, provenance and encoded artifact files are excluded from author input.
- **Pipeline seed.** Copy the narrative create-new mechanics from IEHP batch base commit `4c8fb7e62a78e4d254b89b3053619a759c45e8b1`, which pins CRL 6.4.41 / kit 2.35 and has a Task-aware auditor. This is a seed, **not** a Smile-ready pipeline release. Remove IEHP customer rules, source and artifact history; replace its canonical, outcome, answer-domain, Task-resource, old-artifact and delivery assumptions with explicit Smile-demo bindings. Commit the selected pipeline's instructions, skills, scripts and pins under `.claude/`, plus selected reviewer prompts/protocols under `.vibe-tools/` on the artifact branch, outside KELP-managed entities; place transient candidate work under `tmp/`. Keep the source-first concept inventory, decision tree, CRL skeleton, CEL/MV versus regression, native/session checks, provenance, independent execution, reviews and KELP lifecycle.
- **Selection authority.** The Nautilus orchestrator sets `pipeline_ref`, `profile_ref`, authoring mode and source manifest in an authoritative, immutably identified assignment revision **before** KE launch. The prepared artifact branch carries an exact manifest/hash of the installed `.claude/` and `.vibe-tools/` pipeline and profile bytes; the upstream ref remains provenance. No in-Codespace pipeline picker or KE override. A mismatch or dirty pipeline file pauses dependent work; the orchestration owner issues a new revision and reconciles the run binding. Receipts identify the assignment revision, installed pipeline/profile identities, `kelp.project.json` blob identity and three source-file byte hashes; they do not use artifact branch HEAD as a content identity, because a devcontainer-only converge commit may advance it. An amendment preserves old evidence, marks affected downstream stages invalid, and reruns them before a new qualification claim. Resume reconciles the current assignment revision, checkpoint and artifact state.
- **Version rule.** Pin both selected devcontainer paths and image digests, CRL/kit/engine/driver/MCP, KELP, Automation, agent/reviewer artifacts, pipeline package and profile to the run. Promotion of newer images/packages affects new runs, not active ones. A surviving stopped Codespace can resume on its original image within its retention period. Recovery after deletion is unproven until a per-run ref is demonstrated.
- **Runtime boundary.** The initiating workspace is a Codespace on the KELP image, where the user searches, Locks, opens the Codify card and later returns to Unlock/Complete. The separate authoring Codespace uses the Nautilus image and runs the supervised KE lead. They are distinct Codespaces because their images and roles differ. Nautilus' operator and orchestrator prepare batches and artifact branches; the user-facing Nautilus launch creates or opens the authoring Codespace under the codifier's account. Spaces helps stage both pilot image configurations, but no Spaces service or operator participates when a batch is created or launched. Long-term ownership of the Nautilus image remains undecided.
- **Handoff and identity.** A user identifies a loaded artifact. A Nautilus operator uses the orchestrator skill and agent to prepare its batch assignment and artifact branch with the selected KELP and Nautilus devcontainer configurations; preparation does not create a Codespace or require knowing the eventual codifier. The operator explicitly invokes KELP's readiness action to place it in **Ready for codify**. A separate user finds it with KELP's **Ready for codify** search filter and Locks the codification scopes from the **Codify card**, moving it to **Codify in progress**. The card opens Nautilus, which guides that user through a separate run-associated authoring Codespace on the **Nautilus image**, using the selected devcontainer path, and the preconfigured batch. The codifier KELP Saves, verifies the remote Save and durable handback/review evidence, deletes the authoring Codespace, returns to the initiating Codify card and Unlocks to release ownership. The separate **Complete codify** action advances the artifact to codification review; the existing CRL KE card supports that review, whose own Save, Unlock and **Complete KE** action place it in **Ready to Medical Review** (Ready for MV). Unlock alone never advances a stage. The initiating **KELP-image** Codespace remains available after authoring Codespace deletion; Nautilus excludes its `CODESPACE_NAME` from authoring candidates and prioritizes the batch-recorded authoring Codespace. Reconcile ambiguity with the user. The preferred authoring Codespace display name is `<artifact-id>-assisted-codify`, but a GitHub creation-page fallback may not set it. KELP owns queues, cards and lifecycle; Nautilus owns guided authoring and Codespace launch.

## KELP intake and permissions

For one artifact, KELP Add takes the original HTML as primary source; an authorized content editor then locks source, adds the text extract and metadata as companion files, Saves source, and Unlocks/releases source before downstream authoring. Do not hand-edit `.kelp` records. Verify the complete three-file source snapshot after Save.

KELP Add writes the initial scaffold across configured and reserved entity folders, root `package.json`/`.npmignore`, and `.kelp/produced/source.json`; source-folder-only path permission is insufficient. Lock/Save/Release also modify `.kelp` and selected entity folders and require fetch/push to the artifact branch. Git author email governs lock ownership; GitHub authentication and repository rules govern write access. Spaces/repository administration chooses actual team memberships; KELP specifies no `ke` team.

KELP 0.11 can declare an eight-member card for refined-source, anchor-source, CRL, CEL, CQL, FHIR, QA and provenance; current per-entity/multi-entity lifecycle Lock/Unlock and shared Save are available. The target adds one Codify/Nautilus card alongside the existing CRL KE card and MV lenses; the two KE cards share underlying scopes but serve different teams/stages. KELP's overlapping-card support, card Lock/Unlock and Complete controls, **Ready for codify** search filter and stage transitions are planned, not yet released. The source artifact must be loaded before batch preparation. KELP tracks batch preparation separately from the ready-to-execute queue. An explicit human readiness action after successful batch preparation marks **Ready for codify**; Codify-card Lock marks **Codify in progress**. After Save, Unlock releases ownership and **Complete codify** advances to codification review. KE review then uses the existing CRL KE card; its own completion places the artifact in **Ready to Medical Review**. Unlock alone never advances a stage. KELP can update GitHub Project state on a best-attempt basis and correct it on the next action or refresh; no transaction coordinator is needed. A narrower infrastructure test does not count as passing this full operator workflow.

For interim image and lifecycle staging under KELP 0.11, use one eight-scope Codify/Nautilus card and invoke CRL KE directly if review is exercised. This preserves the codifier's complete scope set. The interim configuration does **not** pass the full two-card or Complete-control workflow. After KELP releases overlapping cards and completion controls, add the CRL KE card over the shared scopes and run the full end-to-end qualification. The existing KE/MV entities and lenses remain in the graph throughout.

Spaces will stage a private repository with the schema-2 KELP graph, scoped repository roles and **two devcontainer configurations**: an initiating KELP image and an authoring Nautilus image. Staging must prove Add, byte-exact source Load, KELP Lock/Save/Release fetch/push, Nautilus card launch from the KELP image, and selection of the Nautilus image for authoring. Only after the graph and both image configurations are tested and promoted to `main` does the intake account perform the real Add/Load of `auto-bleph`. Verify KELP's branch creation behavior. The artifact branch's graph blob, source snapshot and both selectable configurations remain bound to Nautilus's authoritative assignment. Repo-scoped `load` and `codify` permissions are staged without granting new rights on `smile-demo`; intake needs `load`, and the codifier needs `codify`. A staged Add/Load is source intake, not successful codification.

Spaces reports a registry gap: it currently pins one image per target, while this repository needs a different digest for each devcontainer configuration. Its interim authoring image without Nautilus may prove layout, receipts and lifecycle; the full pilot requires the KELP image with Nautilus's launcher and the separate Codify image with the complete Nautilus pipeline and reviewers. Neither interim image evidence nor a devcontainer path alone proves the effective authoring image. Verify the in-Codespace image manifest and startup receipt before authoring.

## Launch, readiness and evidence

The **Nautilus image** must provide the Claude Code VS Code extension as the human-supervised authoring chat, CRL with callable tools, KELP with callable lifecycle tools, Vibe Tools with the configured independent reviewer arms, and the pinned Java/Node/Python/Git dependencies used by the selected pipeline. Nautilus's VS Code extension is required in the initiating KELP image for launch; its presence in the authoring image depends on Nautilus's actual implementation. A Nautilus CLI/MCP may support authoring admission if needed. Codex extension or CLI may support a reviewer arm if that arm requires it; neither replaces the Claude Code authoring entrypoint. Installed extensions alone do not establish callable tools: exercise the actual Claude Code session, CRL, KELP and both review arms.

The authoring Codespace's **only Git checkout** is the content repository at its assigned artifact branch. Batch preparation commits the selected pipeline payload under `.claude/` and `.vibe-tools/` on that branch before the Codespace is created. The user opens Claude Code chat at the checkout root; Nautilus passes the assignment and verifies that the session actually loads the committed pipeline and applicable project instructions. Its hash manifest covers every installed pipeline/profile file, and startup/resume detects a changed or dirty file before using it. The agent uses `tmp/` in the same checkout for disposable candidates, scripts and raw exchanges. There is no KE worktree, pipeline Git bundle or second repository in the authoring Codespace. The image still provides the pinned executables and extensions; it does not have to carry a per-policy pipeline revision.

KELP confirmed from current source that artifact discovery is under `artifacts/`, Save stages only configured entity folders and their basis records, and root `.claude/`, `.vibe-tools/` and `tmp/` are outside those scopes. No KELP config or code change is needed for discovery and scoped Save in this layout; Publish remains a separate qualification. Spaces confirmed that the pilot repo's deny-root `.gitignore` needs explicit `!/.claude/` and `!/.vibe-tools/` allow rules to track the complete payload, while `/.claude/settings.local.json` must remain ignored; root `tmp/` remains untracked scratch. Preserve the batch-era separation of run evidence from published content. Nautilus retains a named remote run ref in the content repository, provisionally `refs/heads/codify-runs/<run-id>`, containing selected checkpoints, amendments, source/pipeline identities, review findings/dispositions, handback and any scripts needed to explain the run. Its receipt records that ref, evidence commit ID, run/assignment ID and KELP-saved artifact commit ID. It needs no second Codespace checkout or worktree. Verify the remote ref and bytes before deleting the authoring Codespace; protect it from Publish cleanup. The implementation that writes this ref remains Nautilus-owned.

**Publish must leave `.claude/`, `.vibe-tools/` and run evidence out of `main` and out of the new ancestry added to `main`.** In current KELP, `kelp release` is Unlock: it updates selected `.kelp` records on the artifact branch and does not integrate `main`. `kelp publish` performs that integration with a merge commit whose parents include the artifact tip. Therefore current Publish would import committed `.claude/` history even after a cleanup deletion. With the agreed pipeline committed on the artifact branch, KELP needs a qualified Publish change that transfers the intended artifact entities plus required KELP-managed metadata, including additions, modifications and deletions, without importing authoring-pipeline/evidence commits into `main`. Record pre-Publish `main`, then verify the new `main` tree and ancestry contain no pipeline or run-evidence paths, that expected artifact and lifecycle changes arrived, and that the retained remote run ref still resolves. Spaces will protect `codify-runs/**` refs against deletion and non-fast-forward updates; Nautilus writes the ref. GitHub rules cannot restrict `.claude/` on `main` without also blocking it on artifact branches, so Publish is the enforcement point. **Do not run current `kelp publish` on an artifact branch carrying committed `.claude/`.** Ordinary `kelp release` remains available for Unlock. The first auto-bleph pilot runs through Codify, KE review and Medical Validation without Publish; the Publish change is a separate, unimplemented gate before integration to `main`. Conflict detection, resume and publication recovery need review for that later gate.
