## KE-method practices and reassessment

Human source read-back, inspection of the delivered rendering, a realistic maintenance amendment, separate inspectability findings, target-client stopping/reopening checks, role independence, accepted-release loading and durable task records are **KE-method practices**. They are not claimed as additional CRL grammar, validator checks or invented kit-force clauses. They complement the mapped source and execution obligations. Their scope and local producer responsibilities remain in the accepted method and actual profiles.

At the KE reference/workflow stage, match the accepted actual tool/runtime and its kit identity. When the kit hash or accepted version changes, retrieve and semantically reassess the mapped entries and in-play prerequisite closure: compare meaning, applicability, individual clause force, supported behavior and evidence limits. Record the change's effect on the method/model and the relevant verification evidence in the existing task/review record. Retrieve complete guidance for any task form outside this map. An unchanged sentence or a passed syntax check does not establish compatibility across a changed runtime.

This is targeted reassessment within the existing workflow, not a new framework or automatic migration rule. The read-only SessionStart loader verifies every manifest-listed installed-default file and injects the available-default SKILL bootstrap and paths. It does not resolve the project binding, read customer profiles, or inject the full references. The agent subsequently resolves the actual binding and active task, loads the accepted release and applicable profiles, and reads the full method and contract map. The loader performs no network retrieval, semantic reassessment or acceptance-state mutation. An unresolved mismatch is reported for the affected reliance, not concealed by silently choosing the newest release. The map's identity and clause indices must be reassessed before claiming compatibility with a different kit.
