# Source-first medical-policy encoding

For CRL 6.4.41 / kit 2.35, the bundled reassessment corrects the accepted method map's older determination-resource example; follow the reassessment and approved customer binding for that point.

Read the run assignment, `.claude/ke-pipeline/ke-method.binding.json`, the accepted neutral method entrypoint and both references, .claude/ke-pipeline/kit-235-reassessment.md, the approved customer binding, the current pipeline contract and the matched CRL kit. Record the identities actually read. The source and authorized refinements supply policy meaning; the binding supplies customer conventions. This skill contains no policy-specific guidance or answer key. Do not consult another encoding of this policy while authoring.

1. Read the complete original and refined source, including qualifications, exclusions, coding notes and scoped customer guidance. Check source-to-refinement correspondence. Identify distinct candidate facts and relationships before choosing constructs. A coding table is a representation clue, not automatically a coverage criterion.
2. Create a source-language decision tree. Establish the assessed supplied Request first. Group source-authorized EIU conditions where applicable. Use a Criterion for a meaningful Boolean condition group; avoid a single-concept wrapper or a catch-all list of unrelated questions. Strongly prefer depth-oriented Decisions for main eligibility progression while preserving source-defined AND/OR, alternatives, exceptions and precedence. A Boolean group may present its questions together; verify the actual questionnaire. Map every tree condition to candidate concepts and source spans.
3. Translate the tree to a CRL decision/Criteria skeleton without flattening meaningful nesting. Implement concepts, finite answer domains, vocabulary, activities and presentation from the matched kit. Use supplied Patient/Request data where supported. Verify a source-provided external request code and its FHIR resource type; otherwise use a clearly local one-option coded Request. Use only source- or customer-authorized answer choices. Missing is unanswered, not No. EIU and uncertainty handling require actual authority, not a generic assumption.
4. Freeze the source model, tree, question proposal and prospective outcomes before predictive runs. Write concise clinician MV cases for each reachable branch, plus a wider regression suite for structure, source representations, negative/missing/overlap/error and boundary controls. Supply an interactive starting Patient+Request Bundle. Run validation, CRE, emission, native controls, FINAL provenance and FHIR identity checks. For HTML/text input, verify UTF-8/NFC, explicit correspondence to HTML, and byte-exact text anchor before provenance. Check native Q/QR resubmission, change, clear, question scope and pauses. A passing compiler or CRE run is not proof of native behavior or source fidelity.
5. Obtain source-first decision and source-only questionnaire reviews with the matching independent lenses. Correct substantive findings and rerun affected gates. Keep source attribution, waivers, technical gaps and human questions explicit. The agent KELP Saves only authored/generated entity work in the content checkout after reconciling locks and the current artifact; the human owns Lock/Unlock and MV approval remains separate. Preserve selected run evidence durably before the Codespace is deleted.
